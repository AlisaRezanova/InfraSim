# InfraSim — аналог

Игра-симулятор проектирования систем: перетаскиваете балансировщик, кэш, БД, очередь, соединяете их и смотрите,
как схема переживает нагрузку и инциденты (задержка, стоимость, ошибки).

## Запуск

| Команда | Что делает |
|---------|-----------|
| `make dev` | Разработка: БД и бэкенд в Docker, фронтенд через Vite (горячая перезагрузка) → http://localhost:5173. Нужны Docker и Node.js |
| `make up`  | Всё в Docker, фронтенд собран и отдаётся nginx → http://localhost:8080. Нужен только Docker |
| `make down` / `make logs` / `make clean` | Остановить / логи / остановить и стереть базу |

Если порт бэкенда 8001 занят: `make dev BACKEND_PORT=9001`.

## Состав

| Часть | Технологии | Что делает |
|-------|-----------|------------|
| `frontend/` | React + Vite, nginx | Интерфейс и **симуляция** (`src/sim.js`, идёт в браузере 10 раз/с) |
| `backend/`  | Python, FastAPI | Отдаёт уровни (`app/levels.py`), сохраняет прогресс и рейтинг |
| `db`        | PostgreSQL 16 | Таблицы `progress` и `survival` (создаются при старте бэкенда) |

nginx проксирует `/api/*` на бэкенд, поэтому наружу торчит только порт 8080.

## API

- `GET /api/levels` — уровни кампании
- `GET /api/progress?player_id=…` / `POST /api/progress` — звёзды по уровням (хранится максимум)
- `POST /api/survival` / `GET /api/leaderboard` — рейтинг режима «Выживание»

Игрок определяется случайным UUID в `localStorage` браузера — без регистрации.

## Модель симуляции

Запросы делятся на чтения и записи и идут по графу от «Пользователей». Каждый блок принимает не больше своей мощности
(лишнее — ошибки), а задержка растёт с загрузкой. Запись в БД стоит 2 единицы, чтение — 1. Кэш и CDN отдают часть чтений сами,
очередь подтверждает запись сразу и копит её в буфере, воркеры разбирают буфер в БД. Отказавший блок выпадает из балансировки.

`standalone.html` — предыдущая версия в одном файле без бэкенда.
